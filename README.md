# Student Life Dashboard

A web app that helps university students manage courses, deadlines, exams, their
weekly timetable, grades/GPA and study time in one place.

> **Status: complete (all 8 stages).** Courses, assignments, exams,
> timetable, grades/GPA, a study tracker, and a **Study Assistant** (rule-based
> plan, plus optional free AI suggestions via Google Gemini through a secure
> server-side function). Password reset, light/dark theme, accessibility
> checks, and a deployment guide. 300+ automated tests, including database
> security and accessibility tests.
> Without Supabase configured,
> the app runs in **demo mode**: the dashboard shows clearly labeled sample
> data, and pages that save data explain that an account is needed.

## Tech stack

## Getting started

Prerequisites: [Node.js](https://nodejs.org/) 20.19+ or 22.12+ (developed on Node 24).

```bash
npm install       # install dependencies
npm run dev       # start the dev server at http://localhost:5173
```

That runs the app in **demo mode**. To sign up and save real data, connect a
free Supabase project by following **[docs/supabase-setup.md](docs/supabase-setup.md)**
(about 10 minutes). The optional AI suggestions need a few more steps:
**[docs/ai-assistant.md](docs/ai-assistant.md)**. To put the app online, see
**[docs/deployment.md](docs/deployment.md)**.

**Key design decisions**
- Calculations live in `src/lib` as *pure functions* (input in, result out; the
  current time is passed in), so they're easy to test and are reused by every page.
- Pages call `src/services`, never Supabase directly. Data access stays in one place.
- **Security lives in the database**, not the frontend. Row Level Security and
  ownership-checked foreign keys stop users reading or linking to anyone else's
  data, even if they bypass the app. See [docs/database.md](docs/database.md).
- Only the public Supabase key is used in the browser. Secrets never go in
  `VITE_` variables, and `.env.local` is git-ignored. The AI key is a
  Supabase secret, used only by the `study-assistant` Edge Function.
- AI is optional and never trusted blindly: the server checks every request
  and every AI answer against a shared format, enforces a daily per-user
  limit, and the AI can't change any data. Without AI, the same page shows a
  rule-based plan.

## Tests

`npm test` runs everything; no Supabase account or internet needed. The full
guide, including a **manual checklist for your real Supabase project**, is in
**[docs/testing.md](docs/testing.md)**.

| Kind | Where | What it checks |
| --- | --- | --- |
| Logic | `src/lib/*.test.ts` | GPA, grades, dashboard stats, study totals, timetable clashes, validation rules |
| Page workflows | `src/pages/*.test.tsx` and others | Clicking through real pages in a simulated browser (database replaced by fakes): create/edit/delete, errors, empty states |
| Navigation | `src/router.test.tsx` | Signed-out users can't reach private pages; crash screen |
| Database | `supabase/tests/` | Real migrations in an in-memory PostgreSQL: RLS, ownership, constraints, the AI daily limit, and that every value a form accepts fits the database |
| AI endpoint | `supabase/tests/study-assistant-function.test.ts` | Sign-in, request checks, daily limit, safe errors, the key never leaks |

## Accessibility

- Every page is checked automatically with [axe-core](https://github.com/dequelabs/axe-core)
  (`src/test/accessibility.test.tsx`). Color contrast was checked in a real
  browser in light and dark mode (WCAG AA).
- Keyboard: a **Skip to main content** link, visible focus outlines, all
  actions reachable without a mouse, and focus moves to the new page after
  navigating. Each page has its own browser-tab title.
- Screen readers: labelled form fields with announced errors, real headings
  in order, status and urgency shown with words and icons (never color alone).
- Respects the device's **reduce motion** setting, and offers light, dark or
  device theme.

## How grades and GPA are calculated

Three levels are kept separate:

1. **Assessment score:** a raw mark, e.g. 42 / 50 (84%).
2. **Course result (calculated):** the weighted average of graded assessments:
   `sum(percent × weight) / sum(weight)`. Assessments without a weight are left
   out rather than guessed. It's labelled with how much of the course is graded
   so far, and shows "Insufficient data" when it can't be calculated. It's a
   guide only; it never becomes the official grade automatically.
3. **Final grade (official):** the letter and/or grade points the student
   enters (picking a letter from their own grading scale fills in its points).
   This is what GPA uses.

```
GPA = sum(grade points × credits) / sum(credits)
```

- Only courses with a **finalized** result that has grade points and more than 0 credits count.
- Every excluded course is reported with a reason (no result, not finalized, missing points, 0 credits).
- If nothing qualifies, the app shows **"Insufficient data"**, never a misleading 0.00.

## Known limitations

- Applying a grading-scale preset is two requests (remove the old scale, then
  add the new one). If the second fails, the scale is left empty; apply the
  preset again.
- The grading scale maps letters to points only; it has no percentage
  ranges, so a calculated course result isn't turned into a letter grade
  automatically (universities' rules differ too much to guess).
- In demo mode only the dashboard shows sample data; pages that save data
  need a real account.
- Timetable classes repeat every week; there's no way yet to skip a week
  (e.g. a holiday) or add a one-off class.
- Clicking an empty timetable slot to add a class needs a mouse; keyboard and
  screen-reader users use the "Add class" button instead.
- Marking a semester as "current" is two requests (un-mark the old one, then
  mark the new one). If the second fails, no semester is current until you
  try again.
- Dates and times are shown in the device's timezone. The timezone in your
  profile isn't used for display; the dashboard points out when the two differ.
- Signing up with an email that already exists shows the same "check your email"
  screen. This is Supabase's deliberate protection against revealing which
  emails have accounts.
- AI suggestions aren't saved: refreshing the page goes back to the
  rule-based plan. The assistant plans for the current semester only.
- The AI daily limit (20 requests per user per 24 hours) is fixed in the
  database; changing it needs a new migration.
- The theme choice is saved per browser, not to your account.
- `npm audit` reports issues in the `shadcn` command-line tool's dependencies.
  The project keeps that package only for a CSS file, and none of its code
  is included in the app that runs in the browser.
