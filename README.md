# Student Life Dashboard

A web app that helps university students manage courses, deadlines, exams, their
weekly timetable, grades/GPA and study time in one place.

> **Current status: Stage 3 of 8.** Accounts, the secured database, and full
> management of semesters, courses and assignments (list + calendar views) are
> done. Exams and the timetable arrive in Stage 4. Without Supabase configured,
> the app runs in **demo mode**: the dashboard shows clearly labeled sample
> data, and pages that save data explain that an account is needed.

## Tech stack

| Concern | Tool |
| --- | --- |
| UI framework | React 19 + TypeScript, built with Vite |
| Styling | Tailwind CSS v4 + shadcn/ui components (`src/components/ui`) |
| Icons / charts | Lucide React / Recharts |
| Routing | React Router |
| Dates | date-fns |
| Forms & validation | React Hook Form + Zod |
| Database & auth | Supabase (PostgreSQL, Auth, Row Level Security) |
| Tests | Vitest, plus PGlite (in-memory PostgreSQL) for database tests |

## Getting started

Prerequisites: [Node.js](https://nodejs.org/) 20.19+ or 22.12+ (developed on Node 24).

```bash
npm install       # install dependencies
npm run dev       # start the dev server at http://localhost:5173
```

That runs the app in **demo mode**. To sign up and save real data, connect a
free Supabase project by following **[docs/supabase-setup.md](docs/supabase-setup.md)**
(about 10 minutes).

## Project structure

```
src/
  components/          Reusable UI pieces
    ui/                shadcn/ui primitives (Button, Card, Dialog, …), generated by the shadcn CLI
    assignments/       Assignment list, calendar, filters, form and dialogs
    auth/              AuthProvider (who is signed in) and route guards
    courses/           Course card, form, and delete dialog (with impact summary)
    dashboard/         Dashboard widgets (stat cards, deadlines, chart, …)
    form/              Form building blocks (field with error, select, color picker, dialog)
    layout/            Sidebar navigation and account menu
    semesters/         Semester selector, form and dialogs
    settings/          Settings page sections
  config/              App-wide config (navigation links)
  hooks/               React hooks (auth, data loading, add/edit/delete editors)
  layouts/             Page shells (app with sidebar; centered auth card)
  lib/                 Core logic, mostly pure and unit-tested
    dashboard-stats.ts   Dashboard numbers (pending, overdue, weekly study time, …)
    assignments.ts       Assignment filtering and sorting
    courses.ts           Course search and "what does deleting this remove?"
    calendar.ts          Month grid for the calendar view
    gpa.ts               Credit-weighted GPA with explained exclusions
    schemas.ts           Zod validation rules for all forms
    supabase.ts          The single Supabase client
    errors.ts            Friendly error messages
    demo-data.ts         Sample data for demo mode
  pages/               One file per route
  services/            All database/auth calls (pages never query Supabase directly)
  test/                Test setup and helpers
  types/               TypeScript shapes of database rows
  utils/               Small formatting helpers
  router.tsx           Route table (public vs. protected pages)
supabase/
  migrations/          SQL that creates the database (tables, constraints, RLS)
  tests/               Database security & constraint tests
docs/
  supabase-setup.md    How to connect Supabase
  database.md          Schema reference and security model
```

**Key design decisions**
- Calculations live in `src/lib` as *pure functions* (input in, result out; the
  current time is passed in), so they're easy to test and are reused by every page.
- Pages call `src/services`, never Supabase directly. Data access stays in one place.
- **Security lives in the database**, not the frontend. Row Level Security and
  ownership-checked foreign keys stop users reading or linking to anyone else's
  data, even if they bypass the app. See [docs/database.md](docs/database.md).
- Only the public Supabase key is used in the browser. Secrets never go in
  `VITE_` variables, and `.env.local` is git-ignored.

## Tests

`npm test` runs three kinds of automated tests:

| Kind | Where | What it checks |
| --- | --- | --- |
| Logic | `src/lib/*.test.ts` | GPA, dashboard stats, filtering/sorting, validation rules, error messages |
| Page workflows | `src/pages/*.test.tsx` | Clicking through real pages in a simulated browser: create, edit, complete and delete assignments; semesters and courses; delete safeguards. The database calls are replaced with in-memory fakes. |
| Database | `supabase/tests/` | The real migration in an in-memory PostgreSQL: RLS, ownership rules, constraints, delete behavior |

## How GPA is calculated

```
GPA = sum(grade points × credits) / sum(credits)
```

- Only courses with a **finalized** result that has grade points and more than 0 credits count.
- Every excluded course is reported with a reason (no result, not finalized, missing points, 0 credits).
- If nothing qualifies, the app shows **"Insufficient data"**, never a misleading 0.00.

## Known limitations (Stage 3)

- Exams, timetable, grades and study sessions can't be created yet (Stages 4–5).
- In demo mode only the dashboard shows sample data; the Courses and
  Assignments pages need a real account, since they save data.
- Marking a semester as "current" is two requests (un-mark the old one, then
  mark the new one). If the second fails, no semester is current until you
  try again.
- No "forgot password" flow yet. Planned for Stage 8.
- Dates and times display in the browser's timezone; the timezone saved in
  Settings isn't applied to display yet.
- Signing up with an email that already exists shows the same "check your email"
  screen. This is Supabase's deliberate protection against revealing which
  emails have accounts.
- The production JS bundle is ~1 MB (~320 kB gzipped), mostly the chart and
  Supabase libraries; code-splitting is planned for Stage 8.
